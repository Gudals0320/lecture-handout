# 내용 대응과 이미지 선별

후처리 Markdown의 H2와 본문 전체를 읽고 그림·수식·예제 숫자·코드·설명 순서로 대응한다. 타임스탬프와 파일명은 단서이며 최종 판정 기준이 아니다.

- 시간 구간이 맞지 않으면 지연·휴식·오프셋·슬라이드 재방문을 감안해 앞뒤 후보를 확인한다. 시간 범위 밖의 더 적합한 화면도 선택한다. 시간이 없으면 내용과 설명 순서로 대응한다.
- 같은 슬라이드의 확대·축소·필기·재방문을 하나의 설명 흐름으로 묶는다. 서로 멀리 떨어진 시각도 같은 슬라이드일 수 있다.
- PPT 애니메이션의 순차 공개를 추적해 완성된 도표·수식·코드·답안을 확보한다. 가장 늦은 화면을 무조건 고르지 않는다.
- 최종 화면 이전에 지워진 유도식과 필기, 확대해서 작성한 주요 설명은 별도로 보존한다. 같은 슬라이드도 전체 화면과 중요한 필기를 여러 장 넣을 수 있다.
- 단순 확대·포인터 이동·내용이 같은 반복은 줄인다. 메뉴가 떠 있더라도 그 화면에만 중요 필기가 있으면 깨끗한 전체 화면과 함께 사용할 수 있다.
- 그림이 없는 절에 엉뚱한 그림을 넣지 않는다. PDF 전체 사용 정책의 예외 처리만 pdf.md를 따른다.
- 각 이미지에는 출처, H2 순번/원문 제목, 내용 기반 선택 이유를 mapping에 기록한다. 타임스탬프나 이전 작업의 순번만으로 대응표를 생성하지 않는다.

H2는 이미지와 본문을 대응시키는 범위이며, 이미지 위치를 H2 바로 아래로 고정하지 않는다. 기본적으로 본문에서 해당 슬라이드의 도표·수식·코드·예제 설명이 시작되거나 테마가 전환되는 문단 직전에 `![내용](./images/파일명.png)`로 넣고 사이에 빈 줄을 둔다. 절 처음부터 설명하는 대표 화면은 H2 아래에 두어도 된다. 후처리 본문·수식·제목·시간·줄바꿈은 수정하지 않는다.

새 합본 작업에서도 별도 재배치 요청을 기다리지 않고 본문 흐름에 따라 분산한다. 한 절 안의 슬라이드 전환, 개념에서 예제로의 이동, 전체 화면에서 세부 필기로의 이동을 실제 내용으로 판단하고 `before_paragraph`로 대상 문단 전체를 대응표에 기록한다. 절 끝의 마무리·참고 교안 페이지처럼 마지막 문단 뒤에 둘 그림은 `after_paragraph`를 쓴다. 일정 문단 수나 이미지 수에 맞춰 기계적으로 등간격 배치하지 않는다. 여러 화면이 같은 설명을 함께 보완하거나 문제·해답 쌍인 경우에는 묶을 수 있다. 설명 본문이 없는 참고 교안을 분산하려고 무관한 문단에 끼워 넣거나 본문·제목을 새로 만들지 않는다.

이미지 재배치만 요청받으면 기존 이미지 링크의 경로·alt·중복 횟수와 실제 이미지 파일을 보존하고 링크 위치만 바꾼다. 이미 잘 대응된 위치는 유지한다. 사용자가 별도 폴더에 모은 배포본의 제자리 수정을 요청하면 그 폴더의 Markdown만 수정하고, 강의 output에도 반영하라는 요청이 있으면 그 위치를 mapping의 `before_paragraph`/`after_paragraph`로 옮겨 `apply`한다. 본문·제목·수식·시간과 링크를 제외한 원문 순서가 보존되는지, 링크 전체 목록과 이미지 해시가 같은지 검증한다.
